# Skill 导入前检查清单

> 面向技能作者与打包者：把一个技能目录（或 zip / 单文件 SKILL.md 的 URL）交给
> DeepWork 安装**之前**，按本清单逐项自查。每一项都标注了「不通过的后果」——
> 其中标 🔴 的项会直接被**拒绝安装**（critical / 清单不合法），标 🟡 的项能装上
> 但会留警告、削弱触发效果或触发体积截断。
>
> 核对基线：`docs/SKILL-INSTALL-CHECK.md`。校验规则以代码为准：
> `packages/core-host/src/skills/manifest.ts`（清单）、
> `packages/core-host/src/skills/audit.ts`（审计）、
> `packages/core-host/src/skills/fetch.ts`（URL 拉取）。

## 一、目录结构

- [ ] 技能是一个**目录**，根下直接放 `SKILL.md`（不是 `README.md`、不是 `docs/SKILL.md`）。
      🔴 根下没有 SKILL.md → 拒绝安装。
- [ ] 打成 zip 发布时，SKILL.md 在**剥掉顶层壳目录后**的根下（GitHub 归档自带
      `repo-main/` 壳，安装时会自动剥一层；SKILL.md 若埋在壳里更深层则找不到）。
      🔴 剥壳后根下无 SKILL.md → 拒绝安装。
- [ ] 目录内不放符号链接。安装时符号链接**既不拷贝也不审计** —— 指到家目录外的
      内容不会被带进来，但链接本身会静默丢失，依赖它的指引会失效。

## 二、frontmatter（SKILL.md 开头的 `---` 围栏）

文件必须以 `---` 开头、以第二个 `---` 闭合；围栏内每行必须是 `key: value` 或
`- 列表项`，解析不了的行**直接报错**（不做宽容解析）。

- [ ] `name` 必填。仅小写字母 / 数字 / 连字符，且以字母或数字开头（kebab-case）；
      不含 `/`、`\`、`.`、`..`。
      🔴 缺失或不合法 → 拒绝安装。
      注意：frontmatter 里的 name 就是安装后的目录名，与磁盘目录名不一致时以它为准。
- [ ] `version` 必填，且是 **semver 写法**：`x.y.z`，可带 `-prerelease` 与 `+build`
      后缀（如 `1.0.0`、`2.1.0-rc.1`）。🟡/🔴 缺失或 `abc`、`1.0` 这类写法 → 拒绝安装。
      升级 = 同名技能传不同的 version（只做字符串相等比较，不做 semver 排序）；
      同名同 version 重复安装是 no-op，不会覆盖 —— 所以**改了内容就必须升 version**。
- [ ] `description` 强烈建议填写（一句话，说清这个技能做什么）。
      🟡 缺失 → 能装上，但记一条 `missing-description` 警告；更严重的是 description
      是语义匹配与 `/` 补全的输入，缺失会让技能「装了却很少被触发」，且界面上只显示
      「（无描述）」。
- [ ] `triggers` 可选：`- 触发场景` 列表，写给内核做语义匹配的提示，建议给 2~5 条
      具体场景（用户会怎么描述任务），不要抄 description。
- [ ] `permissions` 可选：`- fs-read` / `fs-write` / `net` / `shell` 这类声明。
      仅作展示与审计交叉参考 —— 声明不足不会让危险文件漏网，声明过度也不放行。

## 三、正文（frontmatter 之后）

- [ ] 正文是「给内核的指令」，写成**简洁、可执行**的步骤与约定，别写营销文案。
- [ ] 🟡 单个技能正文超 **16,000 字符**会被截断（显式 `/技能名` 调用时），超出的部分
      内核看不到；全部启用技能的注入总量超 **48,000 字符**也会截断。长参考材料拆成
      独立资源文件（见下一条），正文只留指引。
- [ ] 大段参考资料（模板、长文档、示例库）放成目录里的**资源文件**，正文里指路：
      「需要 X 时读取 `<目录>/refs/x.md`」。内核按需自取，不占每轮注入。

## 四、内容安全红线（审计引擎逐文件扫描）

以下命中 **critical** 会被拒绝安装（源目录不进用户机器）：

- [ ] 🔴 破坏性命令：`rm -rf`、`del /S /Q`、格式化、覆盖系统路径等。
- [ ] 🔴 远程执行：`curl ... | sh`、`wget | bash`、PowerShell `EncodedCommand`、
      `Invoke-Expression` 拼接下载内容等。
- [ ] 🔴 混淆载荷：base64/hex 编码后执行的命令、`FromBase64String` 之类。
- [ ] 🔴 可执行二进制：PE（exe/dll）、ELF、脚本类伪装（`report.md.exe` 双扩展名）。
      技能应该是文本 + 静态资源，不要把二进制塞进包里。
- [ ] 🔴 窃取组合：读取凭据/环境变量（`~/.ssh/id_rsa`、`process.env`…）**叠加**
      向外网发请求，单看各自可能只是 warn，组合即 critical。
- [ ] 🔴 zip 炸弹：过度嵌套 / 超大解压比的归档会被拒。

以下命中 **warn**，能装上但会永久留档、展示给用户：

- [ ] 🟡 外部网络请求（curl/wget/fetch 到非 localhost 的 URL）→ `network-egress`。
      确有必要时保留，并在 description/正文里说明为什么、访问谁。
- [ ] 🟡 凭据路径访问（`~/.ssh/`、`id_rsa`、`.aws/credentials`…）→ `secrets-access`。
- [ ] 🟡 携带 `node_modules/` 或 `.git/` → `vendored-deps`：发布为纯静态资源，
      依赖树不可审计。
- [ ] 🟡 单文件超大（逐行扫描上限外）或整包异常偏大 → 留 info/warn 并跳过细扫。

## 五、发布形态

- [ ] 走 URL 发布时：下载上限 **32 MB**、超时 20s；按**内容**判断形态（zip 魔数 /
      `---` 开头），与 URL 后缀无关。单文件形态只接受 SKILL.md 本体，资源文件需打 zip。
- [ ] 包内总大小保持克制：全量文本每轮都要被扫描与（潜在地）注入，几 MB 的纯文本
      包既拖慢审计也容易被体积上限截断。
- [ ] version 变更写在 frontmatter 里，**不要在包里塞 CHANGELOG 之外的多份 SKILL.md**
      （安装只认根下那一份）。

## 六、装完自检（作者在能控制的机器上先装一遍）

- [ ] 安装确认页能正常显示「将要安装：name v version —— 描述」，无「清单不合法」提示。
- [ ] 无 critical 阻断；warn 项都是预期内的。
- [ ] 装后在技能列表看到描述、版本、来源正确。
- [ ] 对话里输入 `/技能名 `（注意尾随空格由补全自动带上）能触发全文注入；
      不输 `/` 时，用 description/triggers 里描述的场景提问，技能能被语义匹配命中。

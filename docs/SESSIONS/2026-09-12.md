按日期归档每次开发会话的**决策与理由**。

与 [DEVLOG.md](../DEVLOG.md) 的分工：DEVLOG 按里程碑记录「做了什么、验证了什么、踩了什么坑」；这里记录「为什么这么定」，也就是那些事后翻代码看不出来的取舍。改代码前值得扫一眼，避免把别人刻意绕开的方案又做一遍。

## 2026-09-12 · M1-E 收尾 + M1-F 打包 · M1 收口到 100%

**范围**：补齐 M1 剩余的交互缺口（逐块授权 / 文件树 / 预览 / 内置终端 / 附件 / 设置 / 会话搜索与重命名），然后完成 electron-builder 打包。**M1 完成度 65% → 100%。**

### 决策与理由

| 决策 | 理由 |
|---|---|
| 内置终端用 `spawn(cmd, {shell})` 而**不做 PTY** | 真 PTY 要引 node-pty，原生模块得跟着 Electron ABI 编译，「装完就能跑」就成了空话。代价是全屏交互程序（vim / top）不可用 —— 这个代价要在面板顶部写明，而不是等用户敲进去再卡住 |
| 终端输出**不进事件日志** | 事件日志是 append-only 且要能字节级分叉/回放；终端输出量大、不可重放（同一条命令两次结果不同），混进去会让「回放出的内容确实是当初发生的那次」这句话失去意义。走独立通知通道、按会话隔离 cwd |
| 文件树变更高亮取自**本次会话的工具差异**，不重新 diff 磁盘 | 高亮要回答的是「这次动了什么」，不是「当前跟 git HEAD 差多少」。重新 diff 会把用户自己手改的文件也算进来，反而误导 |
| 预览把「文件不存在」与「存在但读不出」分成两个字段 | 合成一个空串，界面会把「读不到」显示成「空文件」—— 用户会以为是文件真的空的 |
| 附件只让**用户亲手在对话框选过的路径**进白名单 | 否则渲染层能借预览通道读任意本地文件，绕开审批网关 |
| 逐块授权要求未勾选块**灰显但完整保留** | 不显示就等于用户无法判断自己拒掉的是什么，「逐块」就退化成了盲选 |
| 部分应用**保留原文件行尾风格** | `applySelectedHunks(old, diff, [])` 必须与原文逐字节相同，否则「空勾选」会变成一次静默改写 —— 用户什么都没选，文件却被改了行尾 |
| 演示笔记落点从 `.deepwork/` 挪到工作区根目录 | 前者在文件树里是忽略项，写进去的改动在界面上**看不见**，用户就没法把「审批时看到的差异」与「磁盘上的结果」对上。演示脚本也必须是可信的 |
| 内核产物放 **asar 之外** | 内核是独立 node 进程，读不了 Electron 私有归档格式；塞进去等于堵死「优先用外部 Node 22.19+」这条路 |
| electron 版本钉**精确值** | electron-builder 必须知道确定版本才能下载平台二进制，写 `^44.3.0` 直接报错。Electron 破坏性变更频繁，本来也该锁死 |
| 图标用 `tools/make-icon.js` **代码生成**，不存二进制 | 从界面主题色常量生成（深色圆角底 + 三节点分叉图，分叉是这套工作台最有辨识度的能力）。改主题色重跑脚本即可同步，不需要人工维护一份二进制 |
| 打包验收坚持「能跑」而不是「文件在」 | asar 内的渲染层、asar 外的内核、被清掉的环境变量，每一处都可能「打包成功但应用坏了」。`package-verify.js --launch` 真的启动打包后的 exe 跑一轮任务并截图 —— 正是它抓出了下面两条问题 |
| 修 `host.ready` 丢失用「**先建通道后启动**」，不做事后补发 | 事后补发一个伪造事件能让断言变绿，但 seq 与真实事件流不再对应。调换顺序后事件是真实发出的，seq 天然连续 |

### 顺带修掉的真缺陷

1. **`host.ready` 从未送达过任何客户端** —— 内核先 `host.start()`（内部就 emit）后建 stdio 通道，事件永久丢失。壳层崩溃重启内核后正靠它恢复 UI，丢了就永远卡在「启动中」。此前没暴露，只是因为壳层还有一次主动 `host.status` 轮询兜底。
2. **顶栏标题被挤成一列竖排字** —— 裸文本节点在 flex 行里是匿名伸缩项，中文逐字换行；且容器是横向 flex，把「工作区」按钮摆到了标题右侧。改为外包可截断元素 + 纵向排列。

### 遗留（进入 M2 前的债）

- **真实 Harness 的 headless 契约未校准** —— 全项目唯一硬阻塞。当前 `ENDPOINTS` 与 `EVENT_TYPE_MAP` 是占位约定，内核始终跑在 mock 上。**这是 M2 的第一步**：技能系统、三层记忆、自动化都依赖一个真实底座。
- 自动更新未做（NSIS 只是静态安装包），需要发布通道与版本清单服务，单独评估。
- 未接 CI；仓库无远端。

### 下一步

校准 Harness 契约 → 内核脱离 mock → 再开 M2（技能系统与审计、三层记忆、自动化、MCP、浏览器、Office、用量面板、自动更新）。

## 2026-09-12 · M2-A 契约校准 + M2-B 真实 dsh 端到端 · 协议层与真内核同源

**范围**：校准真实 dsh（ACP）的契约，纠正 M2-A 占位假设；新增真实 dsh 端到端测试，把 32 项一致性断言升级为「协议层 + 真实内核行为」的两层验证。

### 决策与理由

| 决策 | 理由 |
|---|---|
| 真实 dsh 的契约**以真帧为准**，不再读规格示例 | 规格示例与 dsh 实测有三处不同（`session/prompt` 用 `prompt` 数组、能力键 `fs`、权限 id 在 `toolCall.toolCallId`），其余四处（kind 恒为 other、rawInput、嵌套 content、fs/* 不被 dsh 调用）都是「猜就会失败」。先跑 `tools/real-dsh-probe.js` 把真帧打出来再改代码 |
| **fs/* 仍然实现，不删** | 它们是 ACP 规格方法，别的内核可能用；只是 dsh 的 ACP profile 不调用。把它当成「唯一审批依据」会错，把它当「额外闸门」无害 |
| **真正的审批闸门是 `session/request_permission`** | dsh 在写类工具落盘前申请权限，回 `reject-once` 内核就不会写。**fs/* 不是主路径** |
| 风险判定**按工具名**，kind 兜底 | dsh 的 `tool_call.kind` 恒为 "other"，按 kind 判会让所有工具落同一档 —— 表现为「读文件也要弹审批」 |
| 模型用 **`session/set_config_option`** 设置，匹配不上保持默认并记日志 | 模型名对不上只影响用哪个，不该让任务跑不起来 |
| e2e 用 **本地 OpenAI 兼容替身 + 隔离 `$DSH_HOME` + 假凭据** | 端到端不该依赖云端凭据；dsh 的凭据服务一旦在场就屏蔽 env，所以必须写真 `.credentials.yaml`。**用 `--patch` 把凭据插件 `disabled:true` 不顶用**（服务注册还在，env 不被读） |
| 替身 `pickTool` 先**精确名再词边界** | 工具列表里有 `create_goal`，模糊正则 `write\|create` 会让 stub 错命中 `create_goal` —— 报错信息完全不像工具名问题，极难定位 |
| e2e 接受「**工作区内写不触发权限**」的事实，不强行触发 | 触发得用 pwsh（要重写 stub 状态机）或把路径放到工作区外（被 sandbox 直接拦下）。**权限流的真实路径由 conformance 测试（fake agent 强制发 `session/request_permission`）独立验证**，两套测试各管一摊 |
| DevDependency **钉精确版**（`@deepseek-ai/dsh@0.1.5-rc.1`，不要 `^`） | 契约按 0.1.5-rc.1 校准，`^` 范围会被 dist-tag `next` 推到 0.1.5-rc.2，行为可能漂移；下次刷新 lockfile 时也守住 |
| e2e 在 dsh 缺席时 **SKIP 退出码 0** | dsh 是 devDependency，沙箱受限环境装不上时不让 verify 整条变红 |
| 替身与 fixture agent **分开两个文件** | 替身替的是模型（接受 `/v1/chat/completions`），fixture agent 替的是内核（按规格实现 ACP stdio）。两件事不能合并到一个文件 —— 否则测试替身和真实内核行为各说各话 |

### 顺带固化的纪律

- **dp-credentials 屏蔽 env 是 dsh 设计的硬约束**，不是 bug。`resolveApiKey` 先
  `ctx.get("credentials")`，只有该服务不存在才回退 env。任何「关掉凭据插件就能用
  env」的简化假设都是错的。
- **dsh 默认 sandbox-policy = workspace-write**，工作区内写不弹审批 —— 这是 dsh
  的产品选择，不是我们要绕过的限制。**接真生产部署时按 dsh 的行为来设计权限 UI**。
- **`tools/real-dsh-probe.js` 留作取证工具**，断言不住它，但它能让你在不熟悉的
  字段上**先看一眼真帧再写代码**。M2-A 的五处假设错全是被它抓出来的。

### 下一步

1. M2 主体：技能系统（skill 安装 → 目录布局 → 审计字段）。
2. 让 e2e 也能强制触发权限流：增加第二轮 prompt 调 pwsh 工具。
3. 评估 dsh 是否改放 `optionalDependencies`（480 包强制安装代价不小）。

## 2026-09-12 · M2-C 技能系统 · 「先看见再发生」落到磁盘层

**范围**：技能系统的契约、审计引擎、存储管理器、RPC 接线、59 项测试。

### 决策与理由

| 决策 | 理由 |
|---|---|
| **审计必须发生在源目录上、拷贝之前** | 「先拷再审」会让恶意文件先进家门 —— 哪怕随后删除，文件也已经在磁盘上存在过。「已删」和「从未存在」的安全含义完全不同。SkillStore.install 的顺序固定，store-test 28 行专门断言「critical 源未进入家目录」并附 trace |
| **不引 YAML 解析库** | frontmatter 需要的只是 `key: value` 平铺与 `key:` 列表两种形式。引完整 YAML 解析器反而把「frontmatter 能写什么」的边界变模糊（锚点、多文档……），而解析器的模糊边界就是恶意技能的藏身处。60 行手写解析器，多写一行即报错 |
| **审计规则数据驱动（数组 + 正则）** | LINE_RULES 是一张表，加规则就是表里加一行；规则表与 pushLineFindings 分离便于测试与扩展。每条规则 `rule/severity/label/patterns` 四字段一致 |
| **分级是核心 API，不是 UI 细节** | critical 拒绝安装（store 层强制，不落盘）；warn 允许安装但永久留档在清单（UI 可展示「这个技能有什么前科」）；info 仅提示。**不分级的审计等于没审计** |
| **组合升级要新生成一条 finding，不改既有 severity** | secrets + 网络 = exfiltration-combo critical。如果改既有 severity，UI 只能看到一条「critical」消息，不知道是原始规则还是组合结论。新生成一条让 UI 能同时展示原始命中与组合结论 |
| **拷贝跳过符号链接** | `copyDir` 跳过 symlink —— 链接可以指向家目录外，把那种链接搬进来 = 「你装了一个技能，但磁盘上生效的是 ~/.ssh」。这个边界必须由宿主守住，信任源目录等于放弃边界 |
| **name 由 frontmatter 派生而非源目录名** | name 验证 `[a-z0-9][a-z0-9-]*`，拒绝 `.`、`..`、`/`、`\`。把名字从源目录名换成 frontmatter 名并校验重合，可挡「路径分隔符注入」一类利用 |
| **清单与磁盘对齐而非仅信任清单** | `list()` 若发现清单有记录但磁盘没目录，自动剔除并落盘 —— 防手删目录后出现幽灵记录。信任清单等于把磁盘状态拱手让给「过去的自己」 |
| **升级走 `.trash-<name>` 中转** | 同名不同 version：旧目录先移到 `.trash-` 再就位新版本。就位失败能回滚到旧版本再删 trash。不用临时变量语义（`rm -rf` 那种递归删除）写工具函数，名字叫 `rmDirIfExists` 是为名字赤裸以提醒 |
| **审计引擎 ≠ 沙箱** | 规则是按行正则启发式的，挡不住「把命令拆进多行字符串再拼起来」的语义层混淆。深度防御靠运行时的审批网关（写工具、ACP 权限请求）。两层各自承担定位 —— 任何「把这一层改成真正安全」的尝试都会把规则表撑得无法维护 |
| **RPC 白名单必须随协议同步更新** | `apps/desktop/electron/main.js` 的 `ALLOWED_METHODS` 是渲染层唯一能调的入口，漏加白名单意味着 UI 调 5 个 skills.* 都会收「方法不存在」。新方法必须先在协议层定义、再在白名单开放、再在 UI 出现 |
| **审计留档不删** | warn/info 的 finding 永久存在 SkillRecord.audit 里，用户哪天想看「我装的那个技能到底有没有前科」就直接拿这条记录出来。删掉留档 = 把审计从「永久」变成「一次性」 |

### 顺带固化的纪律

- 调试时**写多行函数参数忘了闭合括号** → `node --check tools/<file>` 一次性扫全部语法错误。
  不要一改一跑 —— shell 报错错到第一条就停，看不到第二、第三处。
- 测试断言文本不直接读字符串里嵌的 `await fetch("https://localhost...")`，而是放成 fixture 文件
  让 `fs.writeFileSync` 写进去 —— 这样读者一眼就知道「这是在测什么」。
- 顺手修 SESSIONS 的「唯一硬阻塞」已过时（M2-B 已解），DEVLOG 同步记一行修正。
